# Менеджер Bitrix24 по ИНН (расширение EKLK)

Виджет **«Ваш менеджер»** на главной (дашборд): по ИНН организации из профиля EcomKassa
ищется компания и актуальная открытая сделка в CRM, отображаются контакты ответственного.

Расширение **не влияет** на фискализацию, чеки и платежи.

---

## 1. Создать входящий вебхук в Bitrix24

1. Откройте портал Bitrix24 под администратором.
2. **Разработчикам** → **Готовые сценарии** → **Другое** → **Входящий вебхук**  
   (или: Приложения → Вебхуки → Добавить вебхук → Входящий).
3. Название, например: `EKLK manager by INN`.
4. Права доступа (минимум):

| Право | Зачем |
|--------|--------|
| **CRM** (чтение) | `crm.requisite.list`, `crm.deal.list` |
| **Пользователи** (чтение) | `user.get` — ФИО, email, добавочный |

Если в интерфейсе права дробные — включите чтение **компаний / реквизитов / сделок** и **пользователей**.

5. Сохраните. Скопируйте URL вида:

```text
https://ВАШ_ПОРТАЛ.bitrix24.ru/rest/1/xxxxxxxxxxxxxxxx/
```

Секрет в URL = доступ к CRM. Не коммитьте в git, не светите в чатах.

### Поле добавочного номера

Виджет читает **`UF_PHONE_INNER`** у пользователя.  
Если поля нет: Битрикс24 → Сотрудники → настройка пользовательских полей → внутренний номер  
(или укажите код своего UF-поля и сообщите разработчику для правки).

## 2. Прописать в окружении EKLK

В `.env` на сервере (рядом с остальными переменными EKLK):

```bash
BITRIX24_WEBHOOK_URL=https://ВАШ_ПОРТАЛ.bitrix24.ru/rest/1/xxxxxxxxxxxxxxxx/
# Только сделки из этой воронки (CATEGORY_ID). Пусто = все воронки.
BITRIX24_DEAL_CATEGORY_ID=0
```

### ID воронки

В Bitrix24 у сделок поле **CATEGORY_ID** — номер воронки.

- `0` — обычно общая воронка по умолчанию  
- другие ID — дополнительные воронки  

Как узнать:

1. CRM → Сделки → настройка воронок (в URL или в интерфейсе часто виден id), или  
2. REST: `crm.dealcategory.list` / `crm.category.list` (entityTypeId=2) через тот же вебхук.

Если переменная **пуста** — фильтр по воронке не применяется.

Перезапустите приложение (uvicorn / systemd / docker).

Проверка без UI:

```bash
# подставьте Bearer-токен сессии ЛК
curl -s -H "Authorization: Bearer TOKEN" https://ВАШ-EKLK/api/v1/bitrix/manager
```

Успех:

```json
{
  "success": true,
  "manager": {
    "name": "Иван Иванов",
    "email": "i.ivanov@company.ru",
    "inner_phone": "105"
  }
}
```

ИНН не найден / нет сделок:

```json
{ "success": false, "error": "Компания с таким ИНН не найдена в CRM" }
```

## 3. Данные в CRM

- У компании должен быть **реквизит с ИНН** (`RQ_INN`), совпадающий с `taxIdentity` в профиле EcomKassa.
- Нужна **незакрытая сделка** (`CLOSED = N`) по этой компании.
- У сделки указан **ответственный** (ASSIGNED_BY_ID).

Берётся сделка с максимальным `ID` (самая новая из открытых).

---

## 4. Где в интерфейсе

Главная → колонка справа под метриками → карточка **«Ваш менеджер»**  
(вторичный блок: не перебивает графики, но всегда на виду).

## 5. Код (для сопровождения)

| Файл | Роль |
|------|------|
| `app/services/bitrix_manager.py` | batch-запрос |
| `app/routers/bitrix_manager.py` | `GET /api/v1/bitrix/manager` |
| `app/static/js/sections/dashboard.js` | виджет |
| `app/core/config.py` | `bitrix24_webhook_url`, `bitrix24_deal_category_id` |

Без `BITRIX24_WEBHOOK_URL` виджет покажет сообщение об ошибке конфигурации (ядро ЛК работает как раньше).
